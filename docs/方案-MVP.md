## 一、目标

1. **按考试节奏做整卷模拟**——180 分钟、严格题型配比、计时
2. **持续产出定制题**——按真题结构特征 + 你的薄弱考点加权
3. **薄弱点分析**——按大纲考点聚合，而不是按题号

## 二、范围

### ✅ 做什么（MVP 六件事）

| # | 功能 | 说明 |
| --- | --- | --- |
| 1 | **题库** | 20 年真题客观题全量入库；主观题按「题目 + 采分点 + 挂载考点」入库 |
| 2 | **组卷** | 严格按 311 结构（45 单选 / 3 辨析 / 5 简答 / 3 分析论述，含 30 分必选题） |
| 3 | **模拟** | 显示题目、整卷计时 180 分钟、到点提醒 |
| 4 | **主观题自评** | **你在纸上写 → 系统里勾选你答到的采分点** |
| 5 | **自动记录** | 作答结果、命中率、错因，**无需你手工记账** |
| 6 | **分析报告** | 薄弱考点排行、命中率趋势、错因分布 |

### ❌ 不做什么（明确排除，防止范围膨胀）

| 排除项 | 理由 |
| --- | --- |
| 手机端 | 11 月前不做；先用电脑 |
| 系统内自动判主观题 | 改由**我按 311 批改提示词人工批改**（你手写 → 拍照 → 我读图批改），不经算法判分 |
| 知识库/教材全文检索 | 你直接翻书比在系统里查更快 |
| 知识清单/题库/核心框架（3.8 GB）的处理 | 纯图像、量太大；**按需取用**，不做全量 |
| 押题 / 预测 | 你已同意改做「结构约束采样」 |
| 导入器（批量解析 PDF） | 手工录入当前规模更快；等题库大了再说 |

## 三、主观题流程（已按你的要求定型）

**你手写在纸上 → 拍照发我 → 我读图识别 → 按 311 批改提示词批改 → 结果入库**

| 环节 | 由谁做 | 说明 |
| --- | --- | --- |
| 出题、计时 | 系统 | 按 311 结构组卷 |
| **手写作答** | **你** | 纸上写，完全模拟考场形态 |
| **识别 + 批改** | **我** | 依 `311主观题批改提示词.md`；**先列出「我读到的答案」让你确认**，防识别错误 |
| 记录入库 | 我 | 命中数/总数 + 错因，写入 `学习记录.md` 与数据库 |

**为什么不在系统里做题**：屏幕上打字慢、不像考试；且主观题判分要的是**阅卷判断**，不是算法能力。

**关键约束**：批改由我在对话中完成，**所以必须我在线**。系统负责「出题、计时、存数据」，我负责「批改、分析」。

**拍照要求**（直接决定批改质量）：正对拍摄、不倾斜、四角完整、光线均匀、一页一图、字迹工整——**连笔过重会导致误读**。

## 四、数据模型（草案）

```
outline_nodes   大纲节点：id / 父节点 / 层级（板块·章·节·考点）/ 名称
questions       题目：id / 年份来源 / 题型 / 题干 / 选项 / 正确答案 / 挂载考点
points          采分点：id / 题目id / 序号 / 核心论断 / 判分依据原文
attempts        作答记录：id / 题目id / 日期 / 作答模式 / 命中数 / 总数 / 错因
point_hits      采分点命中：作答id / 采分点id / 是否命中
```

**聚合链**：`采分点命中` → `考点` → **薄弱点排名**。这条链是整个系统的价值所在。

## 五、技术选型

| 项 | 选择 | 理由 |
| --- | --- | --- |
| 后端 | Python + FastAPI | 环境已装好；后续 OCR/数据处理同语言 |
| 数据库 | **SQLite 单文件** | 零部署、可备份、换电脑拷一个文件即可 |
| 前端 | 原生 HTML + JS | **不引入构建工具**——省掉整条前端工具链的维护成本 |
| 运行 | 本地 `http://127.0.0.1:端口` | 双击启动，浏览器打开 |

**明确不用**：React/Vue 构建链、Docker、云服务器、任何需要联网的服务。

## 八、我要提醒你的两个风险

1. **拆点是瓶颈**：20 年真题约 220 道主观题，全部拆完需 40+ 小时。**必须先接受「增量拆、优先拆薄弱点」**，否则第 1 期就会卡死。
2. **最大风险仍是「你会不会用」**：系统做得再好，如果每次用要花 5 分钟准备，你就不会开。所以第 2 期我会优先保证「**双击就开、点两下就开始模拟**」。
