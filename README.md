# 311 备考系统

面向**考研 311（教育学专业基础）**的本地备考工具。Python + FastAPI + SQLite 写成的本地 Web 应用：浏览器访问 `127.0.0.1:8765`，数据存在本地单文件数据库，AI 能力（解析学习记录 / 出题 / 批改）通过 DeepSeek API 调用。

**它和普通刷题工具的区别**：311 主观题占 210 分（约 70%），无法自动判分。本系统把参考答案拆成**可勾选的采分点**，并把每次勾选**聚合到大纲考点**上，从而把"你哪里弱"变成可计算的数据。

## 1. 功能

三个页面共用同一个数据库。

| 页面 | 路径 | 做什么 |
| --- | --- | --- |
| **模拟考试** | `/` | 按 311 真实结构组卷（45 单选 + 3 辨析 + 5 简答 + 3 分析论述，含 30 分必选题），180 分钟计时，客观题自动判分 |
| **日常练习** | `/daily` | 两种入口：① 输入"今天学了什么"（自然语言）→ AI 定位考点 → 出题；② 一键**按薄弱点出题** |
| **练习日志** | `/logs` | 每次练习的得分、采分点命中、以及**当时的薄弱点快照** |

**行为细节**

- **试卷持久化**：刷新页面、关掉重开都拿到**同一份卷子**（`papers` 表记录）。只有点「重新组卷」才换。
- **作答草稿**：每次勾选自动存浏览器本地，刷新后自动恢复并提示。
- **计时连续**：从首次打开那份卷子开始算，不因刷新而重置。
- **主观题批改**：可输入作答文本，或**上传手写照片**（多模态识别后按规则批改，并回显识别内容供核对）。
- **AI 批改保留「言之有理」加分项**：采分点之外但论述成立的内容单独标注，**不计入命中率**。

## 2. 三个核心设计决策

这三条决定了整个系统的形状，改动它们会牵动几乎所有模块。

### 决策一：主观题靠「勾选采分点」量化，而不是让 AI 打分

```
参考答案 ──拆解──▶ 4–6 个采分点 ──作答后勾选──▶ 命中率 ──聚合──▶ 考点强弱
```

**为什么**：主观题没有唯一正确答案，AI 打分不可复现（同一答案两次可能不同），且倾向给"人情分"。一旦打分不可信，下游所有"薄弱点分析"都是垃圾——**输入数据的可信度就是整个系统的上限**。

**代价**：依赖采分点已经拆好，所以数据管线里专门有一环（`ingest_subjective.py`）批量拆点。

### 决策二：一切挂到「大纲考点」上，而不是挂在题号上

```
point_hits（采分点命中）┐
                        ├─▶ outline_nodes（大纲节点）─▶ 薄弱点排名
attempts（客观题对错）  ┘
```

题目挂在 `section`（大纲的"节"）级；采分点也带 `outline_id`。这样"第 46 题错了"才可能变成"**教育学原理 › 教育目的与培养目标** 这块弱"。

**为什么**：按题号聚合没有指导意义——需要知道的是"哪个知识点要补"，不是"哪道题做错过"。

### 决策三：AI 只做它擅长的事

| 交给 AI | 不交给 AI |
| --- | --- |
| 自然语言 → 考点映射（`/api/daily/parse`） | 客观题判分（比对字符串即可） |
| 真题不够时生成新题 | 薄弱点统计（SQL 聚合更可靠） |
| 主观题批改（按固定规则） | 判定哪些算"薄弱点"（阈值由人定） |

**为什么**：AI 适合处理模糊输入，不适合做确定性计算。让 AI 去做 SQL 能做的事，只会引入不确定性。

## 3. 快速开始

### 依赖

```bash
pip install fastapi "uvicorn[standard]" pymupdf rapidocr-onnxruntime opencv-python
```

（`pymupdf` / `rapidocr` / `opencv` 仅数据管线需要；只跑服务的话 `fastapi` + `uvicorn` 就够）

### 配置

```bash
cp config.example.json config.json
# 编辑 config.json，填入 DeepSeek API key
```

`config.json` 已被 `.gitignore` 忽略，**不会被提交**。

### 启动

```bash
# Windows：双击 启动系统.bat
# 或命令行：
cd app
python -m uvicorn server:app --host 127.0.0.1 --port 8765
```

打开 <http://127.0.0.1:8765>。

> **注意**：首次运行 `data/kaoyan.db` 是空的，页面能打开但没有题目，
> 需要先按[第 7 节](#7-数据管线从-pdf-到题库)把题库建起来。

### 成本

`deepseek-flash` 下，每天（解析记录 + 出题 + 批改 3 道主观题）约 **0.05 元**。DeepSeek 采用峰谷定价，晚间使用半价。

## 4. 系统架构

### 4.1 分层

```
┌──────────────────────────────────────────────┐
│  浏览器                                       │
│  static/index.html   模拟考试                 │
│  static/daily.html   日常练习                 │
│  static/logs.html    练习日志                 │
│  （原生 HTML/JS，无构建工具）                  │
└───────────────────┬──────────────────────────┘
                    │  HTTP  (127.0.0.1:8765)
┌───────────────────▼──────────────────────────┐
│  app/server.py   FastAPI                     │
│  ┌────────────────────────────────────────┐  │
│  │ 业务：组卷 / 判分 / 薄弱点 / 日志 / 试卷   │  │
│  │ AI  ：转发到 ai.py，并把结果落库          │  │
│  └────────────────────────────────────────┘  │
└────────┬─────────────────────────┬───────────┘
         │                         │
┌────────▼────────┐      ┌─────────▼──────────┐
│ data/kaoyan.db  │      │ app/ai.py          │
│ SQLite 单文件    │      │ 读 config.json     │
│ 7 张表          │      │ → DeepSeek API     │
└─────────────────┘      └────────────────────┘
```

**模块职责**

| 文件 | 职责 | 依赖 |
| --- | --- | --- |
| `server.py` | 全部 HTTP 接口；业务逻辑与 SQL | SQLite、`ai.py` |
| `ai.py` | 封装 AI 调用（三个业务函数 + JSON 容错） | `config.json`、DeepSeek API |
| `build_db.py` 等 | 数据管线（离线跑，不参与运行时） | 无 |
| `static/*.html` | 界面（各自独立，共用同一套接口） | 无 |

### 4.2 三条典型请求链路

**A. 模拟考试**

```
GET  /api/paper
  ├─ papers 表有 status='active' 的记录？
  │    └─ 有 → 按 id 列表还原题目（刷新不换卷）
  └─ 没有 → 抽题
              ├─ 真题库随机取（按 311 结构 45/3/5/3）
              ├─ 缺口 → ai.generate_questions() 生成并入库
              └─ 写入 papers（旧的置为 archived）

POST /api/save
  ├─ 客观题：questions.answer 与提交答案比对 → hits=0/1
  ├─ 主观题：记录勾选的采分点 → point_hits
  ├─ 写 attempts
  ├─ 计算当前薄弱点 → 快照写入 sessions
  └─ 返回客观题得分
```

**B. 日常练习**

```
POST /api/daily/parse
  输入：自然语言学习记录 + 大纲"节"清单
  输出：AI 选出的候选考点（含置信度与依据）→ 前端让使用者增删

POST /api/daily/generate        ← 按指定考点出题
POST /api/daily/weak-paper      ← 按薄弱点出题（不用填记录）
  ├─ 查 /api/weakness，取命中率最低且样本量足够的考点
  └─ 与 generate 共用组卷逻辑

POST /api/daily/grade
  输入：题目 + 采分点 + （作答文本 | 手写照片）
  输出：得分 / 命中采分点 / 遗漏 / 错因 / 逐段批注 / 优化版作答
```

**C. 薄弱点统计**

```sql
-- 分子分母口径必须一致：一次判定机会 = 1 个样本
--   客观题：一次作答 = 1 样本（对 = 1）
--   主观题：一次作答 × 一个采分点 = 1 样本（命中 = 1）

UNION ALL ─▶ JOIN outline_nodes ─▶ GROUP BY 节点 ─▶ 命中率升序
```

## 5. 数据模型

SQLite 单文件 `data/kaoyan.db`，7 张表。

### outline_nodes — 大纲骨架

| 字段 | 说明 |
| --- | --- |
| `id` / `parent_id` | 树形结构（自引用） |
| `level` | `board` / `chapter` / `section` / `point` / `detail` / `goal` |
| `name` | 节点名 |
| `seq` | 同级顺序 |
| `path` | 完整路径，如 `中外教育史 › 五、外国近代教育 ›（三）西欧近代教育思想与教育思潮` |
| `code` | 编号（`一、` / `（一）` / `1.`） |

### questions — 题目

| 字段 | 说明 |
| --- | --- |
| `year` | 年份（AI 生成为 NULL） |
| `source` | `2021真题·单选` / `2021真题·主观` / `AI生成` |
| `qtype` | `single` / `analysis`(辨析) / `short`(简答) / `essay`(分析论述) |
| `stem` | 题干（材料题保留 `\n` 分段） |
| `options` | JSON，如 `{"A":"…","B":"…"}` |
| `answer` | 客观题答案（A/B/C/D） |
| `outline_id` | → `outline_nodes.id`，挂载的考点 |
| `extra` | JSON，主观题存 `{"full_score": 15}` |

### points — 采分点（系统的核心资产）

| 字段 | 说明 |
| --- | --- |
| `question_id` | → `questions.id` |
| `seq` | 序号，用于勾选 |
| `claim` | **核心论断**（短，用于勾选按钮） |
| `evidence` | **判分依据**（长，贴近参考答案原文） |
| `outline_id` | 该点所属考点（薄弱点聚合靠它） |

### attempts / point_hits — 作答记录

`attempts`：`question_id` / `date` / `mode` / `hits` / `total` / `cause` / `note`

- 客观题：`hits=0/1`，`total=1`
- 主观题：`hits=命中采分点数`，`total=该题采分点总数`

`point_hits`：`(attempt_id, point_id, hit)` —— 具体命中了哪些点。

### sessions — 练习日志

每次提交一条：得分、采分点命中、`weak_snapshot`（当刻薄弱点快照 JSON）。

### papers — 试卷持久化

`single_ids` / `subjective_ids`（JSON 数组，**保持顺序**）、`status`（`active` / `archived`）。

## 7. 数据管线：从 PDF 到题库

**本仓库不含任何真题 / 教辅 / 大纲 PDF**（版权原因）。有自己的资料时，按下面顺序处理：

```
① PDF/扫描件  ──OCR──▶  source/真题库/*.md
        tools/ocr_pages.py + RapidOCR
        （先渲染 300 DPI 再识别；扫描件无文字层时必需）

② 真题文本    ──AI──▶  questions（单选）
        app/ingest_years.py
        （把真题原文 + 解析原文一起交给 AI，一次输出结构化题目与答案）

③ 真题文本    ──AI──▶  questions + points（主观题 + 采分点）
        app/ingest_subjective.py

④ 大纲文本    ──规则──▶  outline_nodes
        app/build_db.py
        （正则解析 Markdown 层级，无需 AI）

⑤ 全部题目    ──AI──▶  questions.outline_id
        app/tag_questions.py
        （把题干交给 AI，从大纲"节"清单里选一个）
```

**脚本共性**：都支持 `--force` 重做、按年份过滤（如 `ingest_years.py 2021`），且**单个文件失败不中断整批**（异常隔离）。

**成本参考**：18 年真题（约 800 道单选）+ 193 道主观题（847 个采分点）+ 挂载考点，合计 **约 1 元**。

## 8. 关键实现与理由

以下都是实际踩过坑之后定下来的，改动前请先理解原因。

### 8.1 AI 生成的选项必须在程序层打乱

实测 AI 生成的单选题答案高度集中在某个字母（连出 3 道全是 B），考生会看出规律。在 prompt 里要求"均衡分布"**不可靠**，所以 `ai.shuffle_options()` 在代码里打乱选项并同步更正答案。

### 8.2 薄弱点的分子分母口径必须一致

```
每个「样本」= 一次判定机会
  客观题：一次作答 = 1 样本（对 = 1）
  主观题：一次作答 × 一个采分点 = 1 样本（命中 = 1）
```

早期版本分子来自 `point_hits`（只记命中）、分母来自 `points`（全部采分点），两边口径不同，**出现过 `2/1 = 200%` 这种不可能的结果**。

### 8.3 思考模式默认关闭

实测同一个问题：开启思考输出 **44 tokens**，关闭只需 **1 token**，而思考 token 按输出计费（4 元/百万）。所以 `config.json` 里 `thinking: "disabled"`，只在批改主观题时由代码单独开启。

### 8.4 判断 PDF 质量不能只看单一指标

判断扫描件能否直接抽文字时，这些"直觉指标"都会被绕过：

| 指标 | 失效场景 |
| --- | --- |
| 字节数够多 | 嵌入字体缺 ToUnicode → 抽出全是乱码 |
| 中文占比高 | 页面全是水印 → 有中文但无有效内容 |
| 占比正常 | 文字层只覆盖前几页 → 内容残缺 |

**可靠的办法是抽出来看几眼。** `tools/audit_pdf_quality.py` 用「中文占比 + 每页字符数 + 最高频行占比」三指标做初筛，但最终仍需人工抽查。

### 8.5 试卷必须持久化

早期每次请求 `/api/paper` 都重新随机组卷，结果刷新页面就换卷、作答全丢。现在 `papers` 表记录当前生效的卷子，只有显式 `rebuild=1`（前端「重新组卷」）才归档旧的、生成新的。

### 8.6 前端事件绑定的选择器要与实际 DOM 一致

草稿自动保存曾经完全不生效，原因是绑定用了 `#paper input`，而**页面上根本没有 `#paper` 元素**（真正容器是 `#singles` / `#subjectives`）。这类错误不报错，只静默失效——**验证方式是在浏览器里实际点一下，看数据有没有写入**。

## 11. 已知限制

- **不含题库**：需自备真题资料
- **AI 定位考点可能出错**：所以保留「考点确认」步骤，由使用者增删后再出题
- **AI 生成题质量需要观察**：生成题标记 `source='AI生成'`，不参与"真题优先"抽取
- **薄弱点分析精度取决于作答量**：作答覆盖的考点太少时，分析会集中在少数节点上
- **题目挂载粒度不完全统一**：绝大多数挂 `section`，少量是 `point`
- 手机端未适配（局域网可访问，但布局未优化）
