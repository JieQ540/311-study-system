# 311 备考系统

> 面向**考研 311（教育学专业基础）**的本地备考工具：跨年份真题模拟 + 日常练习 + AI 批改 + 薄弱点分析。

一个可以直接跑在自己电脑上的学习系统。数据全部存在本地 SQLite 单文件里，AI 能力通过 API 接入，**不依赖任何在线服务**。

---

## 它想解决什么问题

| 痛点 | 做法 |
| --- | --- |
| 311 主观题占 210 分（约 70%），**没法自动判分** | 把参考答案拆成 **4–6 个可勾选的采分点**；练习时自评勾选，或交给 AI 按同一份评分规则批改 |
| 刷题工具只知道"你错了"，**不知道你哪里弱** | 采分点命中与客观题对错都**聚合到大纲考点**上，产出薄弱点排序 |
| 模拟卷只能按年份买，**无法按自己的弱项定制** | 跨年份随机组卷 + 按薄弱点定向出题 + 真题不够时用 AI 按大纲生成 |

---

## 功能

| 页面 | 功能 |
| --- | --- |
| `/` **模拟考试** | 严格按 311 结构组卷（45 单选 + 3 辨析 + 5 简答 + 3 分析论述，含 30 分必选题），180 分钟计时，客观题自动判分 |
| `/daily` **日常练习** | 输入"今天学了什么"（自然语言）→ AI 定位大纲考点 → 出题 → 作答 → 批改；也可**一键按薄弱点出题** |
| `/logs` **练习日志** | 每次练习的得分、采分点命中、以及**当时的薄弱点快照**，可回看进步轨迹 |

**几个实现细节**：

- **试卷会持久化**：刷新页面、关掉重开都拿到同一份卷子，未提交的作答自动存本地草稿并恢复；只有主动点「重新组卷」才换卷
- **计时器跨刷新连续**：从首次打开那份卷子开始算，不会因为刷新而重置
- **支持手写照片批改**：主观题拍纸上答案上传，多模态识别后按 311 评分规则批改，并回显识别内容供核对
- **AI 批改保留「言之有理」加分项**：采分点之外但论述成立的内容单独标注，**不计入命中率**（避免污染薄弱点数据）

## 快速开始

```bash
# 1. 依赖
pip install fastapi "uvicorn[standard]" pymupdf rapidocr-onnxruntime opencv-python

# 2. 配置 API key
cp config.example.json config.json
# 编辑 config.json，填入你的 DeepSeek API key（config.json 已被 .gitignore 忽略）

# 3. 启动
#   Windows：双击 启动系统.bat
#   或命令行：
cd app
python -m uvicorn server:app --host 127.0.0.1 --port 8765
```

打开 <http://127.0.0.1:8765>。

> **成本参考**：用 `deepseek-flash`，每天（解析记录 + 出题 + 批改 3 道主观题）约 **0.05 元**，一个月 1–2 元。
> DeepSeek 采用峰谷定价，晚间使用是半价。

**本仓库不包含任何真题、教辅或大纲 PDF**——这类资料有版权，请自行准备并遵守当地法律。

仓库里只有**代码**、**方法论文档**，以及一份**大纲骨架**（`source/骨架.md`，四大板块 › 章节 › 考点的层级结构）。

如果你有自己的资料，数据管线的重建顺序是：

```
① PDF/扫描件  ──OCR──▶  source/真题库/*.md        （tools/ocr_pages.py + RapidOCR）
② 真题文本    ──AI──▶  questions（单选）          （app/ingest_years.py）
③ 真题文本    ──AI──▶  questions + points（主观）  （app/ingest_subjective.py）
④ 大纲文本    ──规则──▶  outline_nodes             （app/build_db.py）
⑤ 全部题目    ──AI──▶  questions.outline_id        （app/tag_questions.py）
```

各脚本都支持 `--force` 重做、按年份过滤，且**单个文件失败不会中断整批**。


## 几个值得说的技术点

**1. AI 输出全部走 JSON，且选项在程序层打乱**

实测 AI 生成的单选题答案会高度集中在某个字母（连出 3 道全 B），考生会看出规律。prompt 里要求"均衡分布"并不可靠，所以**在代码里打乱选项并同步更正答案**。

**2. 薄弱点统计的口径必须一致**

```
每个「样本」= 一次判定机会
  客观题：一次作答 = 1 样本（对 = 1）
  主观题：一次作答 × 一个采分点 = 1 样本（命中 = 1）
```

早期版本的分子来自 `point_hits`（只记命中）、分母来自 `points`（全部采分点），两边口径不同，**出现过 `2/1 = 200%` 这种不可能的结果**。

**3. 判断 PDF 质量不能只看一个指标**

判断扫描件能否直接抽文字时，"字节数够多"和"中文占比高"都会被绕过：

- 嵌入字体缺 ToUnicode → 抽出乱码，但字节数正常
- 页面上全是水印 → 中文占比很高，但没有有效内容
- 文字层只覆盖前几页 → 占比正常但内容残缺

**最终可靠的办法是抽出来看几眼。**

**4. 思考模式很贵，默认关掉**

实测同一个问题：开启思考输出 44 tokens，关闭只需 1 token，而思考 token 按输出计费（4 元/百万）。所以 `thinking: disabled` 是默认值，只在批改这种需要判断力的场景下才开。

## 已知限制

- **不含题库**：需要自备真题资料（见上文）
- **AI 定位考点可能出错**：所以日常练习保留了「考点确认」这一步，由使用者增删
- **AI 生成题质量需要观察**：生成题标记为 `AI生成`，不参与"真题优先"抽取
- **薄弱点分析的精度取决于作答量**：作答覆盖的考点太少时，分析会集中在少数节点上
- 手机端未适配（本地局域网访问可行，但布局未优化）
