# 311 备考系统

面向**考研 311（教育学专业基础）**的本地备考工具。Python + FastAPI + SQLite 写成的本地 Web 应用：浏览器访问 `127.0.0.1:8765`，数据存在本地单文件数据库，AI 能力（解析学习记录 / 出题 / 批改）通过 DeepSeek API 调用。

**它和普通刷题工具的区别**：311 主观题占 210 分（约 70%），无法自动判分。本系统把参考答案拆成**可勾选的采分点**，并把每次勾选**聚合到大纲考点**上，从而把"你哪里弱"变成可计算的数据。

## 1. 功能

四个页面共用同一个数据库，外加两处薄弱点/复盘入口。

| 页面 | 路径 | 做什么 |
| --- | --- | --- |
| **模拟考试** | `/` | 按 311 真实结构组卷（45 单选 + 3 辨析 + 5 简答 + 3 分析论述，含 30 分必选题），180 分钟计时，客观题自动判分；**交卷后可看每题答案与解析** |
| **日常练习** | `/daily` | 两种入口：① 输入"今天学了什么"（自然语言）→ AI 定位考点 → 出题；② 一键**按薄弱点出题**。带「**出题设置**」：五档难度 + 思考模式开关（默认开，可随时关） |
| **练习日志** | `/logs` | **按天分组**；展开某一天可看到当天做过的每一道题——题干、你的作答、批改情况（客观题对错 + 主观题采分点逐点命中 / AI 批改），并可直接生成或跳转该次的 AI 复盘 |
| **学习复盘** | `/reports` | 每次练习生成一份**基于数据**的 AI 学习报告（得分/失分考点/趋势/下一步），并画正确率趋势图；每条都能跳回练习日志看**这次到底做了哪些题** |
| **薄弱点分析** | 各页入口 | 客观题对错 + 主观题采分点命中，按大纲考点聚合排序 |

**行为细节**

- **试卷持久化**：刷新页面、关掉重开都拿到**同一份卷子**（`papers` 表记录）。只有点「重新组卷」才换。
- **作答草稿**：每次勾选自动存浏览器本地，刷新后自动恢复并提示。
- **计时连续**：从首次打开那份卷子开始算，不因刷新而重置。
- **主观题批改**：可输入作答文本，或**上传手写照片**（多模态识别后按规则批改，并回显识别内容供核对）。
- **AI 批改保留「言之有理」加分项**：采分点之外但论述成立的内容单独标注，**不计入命中率**。

## 2. 三个核心设计决策

这三条决定了整个系统的形状，改动它们会牵动几乎所有模块。

### 决策一：主观题靠「勾选采分点」量化，而不是让 AI 打分

```
参考答案 ──拆解──▶ 4–6 个采分点 ──作答后勾选──▶ 命中率 ──聚合──▶ 考点强弱
```

**为什么**：主观题没有唯一正确答案，AI 打分不可复现（同一答案两次可能不同），且倾向给"人情分"。一旦打分不可信，下游所有"薄弱点分析"都是垃圾——**输入数据的可信度就是整个系统的上限**。

**代价**：依赖采分点已经拆好，所以数据管线里专门有一环（`ingest_subjective.py`）批量拆点。

### 决策二：一切挂到「大纲考点」上，而不是挂在题号上

```
point_hits（采分点命中）┐
                        ├─▶ outline_nodes（大纲节点）─▶ 薄弱点排名
attempts（客观题对错）  ┘
```

题目挂在 `section`（大纲的"节"）级；采分点也带 `outline_id`。这样"第 46 题错了"才可能变成"**教育学原理 › 教育目的与培养目标** 这块弱"。

**为什么**：按题号聚合没有指导意义——需要知道的是"哪个知识点要补"，不是"哪道题做错过"。

### 决策三：AI 只做它擅长的事

| 交给 AI | 不交给 AI |
| --- | --- |
| 自然语言 → 考点映射（`/api/daily/parse`） | 客观题判分（比对字符串即可） |
| 真题不够时生成新题 | 薄弱点统计（SQL 聚合更可靠） |
| 主观题批改（按固定规则） | 判定哪些算"薄弱点"（阈值由人定） |

**为什么**：AI 适合处理模糊输入，不适合做确定性计算。让 AI 去做 SQL 能做的事，只会引入不确定性。

## 3. 快速开始

> **本仓库已随包带题库**，clone 下来**不配任何东西**就能组卷、做题、判分、看薄弱点。
> AI 功能（出题 / 批改 / 复盘）可选，需要自己的 DeepSeek API key。

### 依赖

需要 **Python 3.10 或更高版本**（Windows 安装时记得勾选 `Add python.exe to PATH`）。

```bash
pip install fastapi "uvicorn[standard]"
```

（只跑服务就够。数据管线另需 `pymupdf` / `rapidocr-onnxruntime` / `opencv-python`；
批改手写照片不需要额外依赖，走 API 的多模态能力）

### 启动

```bash
# Windows：双击 启动系统.bat
#   —— 它会自己检查 Python 和依赖：缺依赖自动装（约 1 分钟），缺 Python 会告诉你装哪个；
#      并且等端口真的起来了才打开浏览器，不会让你先看到一个「无法访问」的页面。
# 或命令行：
cd app
python -m uvicorn server:app --host 127.0.0.1 --port 8765
```

打开 <http://127.0.0.1:8765> 即可开始做题。

**服务怎么找到题库**（逻辑集中在 `app/dbpath.py`，启动时决定一次）：

1. 有 `data/kaoyan.db` 且**里面真的有表** → 用它（你的作答记录都在这里）；
2. 没有、或那个文件不是可用的库（0 字节 / 损坏 / 建表中途失败）→ 把随包的
   `data/kaoyan-seed.db` **复制**出一份 `data/kaoyan.db` 再用它；
   原文件非空时会先备份成 `data/kaoyan.db.bak-<时间戳>`，不会静默删掉你的东西。

> 为什么不是「直接用 seed 库」：`kaoyan-seed.db` 是**被 git 跟踪**的随包文件。
> 把练习记录写进去，会让 `git checkout .` / 重新 clone / `git stash` **静默抹掉
> 全部学习历史**，以后 `git pull` 也必然冲突。所以你自己的数据一律进 `kaoyan.db`
> （已 gitignore，可直接拷走备份）。
>
> 测试用途可以用环境变量 `DSH_DB` 把库指到临时副本上，此时不会复制任何文件。

### 配置（可选，只有 AI 功能需要）

```bash
cp config.example.json config.json
# 编辑 config.json，填入你自己的 DeepSeek API key
```

`config.json` 已被 `.gitignore` 忽略，**不会被提交**。
没配 key 时不会崩：AI 相关接口会返回一句人话提示（"请先复制 config.example.json 并填入 key"），
组卷、判分、薄弱点、练习日志照常可用。

`deepseek-flash` 下，每天（解析记录 + 出题 + 批改 3 道主观题）约 **0.05 元**。DeepSeek 采用峰谷定价，晚间使用半价。

### 随包数据（`data/kaoyan-seed.db`，约 1.8 MB）

| 内容 | 数量 |
| --- | --- |
| 大纲节点 | 637 个（4 板块 › 35 章 › 135 节 › 441 考点） |
| 题目 | **1057 道**（真题 1001，覆盖 2009–2026 共 18 个年份；AI 生成 56） |
| 采分点 | **912 个**（每道主观题 3–6 个，全部挂到大纲考点） |
| 个人数据 | **无**（作答记录 / 练习日志 / 复盘报告均为空，你自己用才有） |
| 解析长文 | **不含**（见下） |

**关于解析**：本仓库只收录**真题题干与官方答案**。客观题解析与主观题参考答案那部分
逐字来自商业机构的解析书，未随仓库分发。想补全：
把你的解析文本按 `YYYY年311教育学解析.md` 放进 `source/真题库/解析/`，然后

```bash
cd app
python extract_explain.py            # 客观题解析 → extra.explain
python extract_subjective_answer.py  # 主观题参考答案 → extra.answer_text
```

两个脚本都是**规则抽取、不调用 AI、不花钱**，跑完交卷后页面上就能看到解析。

## 4. 系统架构

### 4.1 分层

```
┌──────────────────────────────────────────────┐
│  浏览器                                       │
│  static/index.html   模拟考试                 │
│  static/daily.html   日常练习                 │
│  static/logs.html    练习日志                 │
│  （原生 HTML/JS，无构建工具）                  │
└───────────────────┬──────────────────────────┘
                    │  HTTP  (127.0.0.1:8765)
┌───────────────────▼──────────────────────────┐
│  app/server.py   FastAPI                     │
│  ┌────────────────────────────────────────┐  │
│  │ 业务：组卷 / 判分 / 薄弱点 / 日志 / 试卷   │  │
│  │ AI  ：转发到 ai.py，并把结果落库          │  │
│  └────────────────────────────────────────┘  │
└────────┬─────────────────────────┬───────────┘
         │                         │
┌────────▼────────┐      ┌─────────▼──────────┐
│ data/kaoyan.db  │      │ app/ai.py          │
│ SQLite 单文件    │      │ 读 config.json     │
│ 9 表 + 3 视图    │      │ → DeepSeek API     │
└─────────────────┘      └────────────────────┘
```

**模块职责**

| 文件 | 职责 | 依赖 |
| --- | --- | --- |
| `server.py` | 全部 HTTP 接口；业务逻辑与 SQL | SQLite、`ai.py`、`dbpath.py` |
| `ai.py` | 封装 AI 调用（三个业务函数 + JSON 容错） | `config.json`、DeepSeek API |
| `dbpath.py` | 决定读写哪个库（用户库 / 随包 seed 的复制） | 无 |
| `build_db.py` 等 | 数据管线（离线跑，不参与运行时） | 无 |
| `static/*.html` | 界面（各自独立，共用同一套接口） | 无 |

### 4.2 三条典型请求链路

**A. 模拟考试**

```
GET  /api/paper
  ├─ papers 表有 status='active' 的记录？
  │    └─ 有 → 按 id 列表还原题目（刷新不换卷）
  └─ 没有 → 抽题
              ├─ 真题库随机取（按 311 结构 45/3/5/3）
              ├─ 缺口 → ai.generate_questions() 生成并入库
              └─ 写入 papers（旧的置为 archived）

POST /api/save
  ├─ 客观题：questions.answer 与提交答案比对 → hits=0/1
  ├─ 主观题：记录勾选的采分点 → point_hits
  ├─ 写 attempts
  ├─ 计算当前薄弱点 → 快照写入 sessions
  └─ 返回客观题得分
```

**B. 日常练习**

```
POST /api/daily/parse
  输入：自然语言学习记录 + 大纲"节"清单
  输出：AI 选出的候选考点（含置信度与依据）→ 前端让使用者增删

POST /api/daily/generate        ← 按指定考点出题
POST /api/daily/weak-paper      ← 按薄弱点出题（不用填记录）
  ├─ 查 /api/weakness，取命中率最低且样本量足够的考点
  └─ 与 generate 共用组卷逻辑

POST /api/daily/grade
  输入：题目 + 采分点 + （作答文本 | 手写照片）
  输出：得分 / 命中采分点 / 遗漏 / 错因 / 逐段批注 / 优化版作答
```

**C. 薄弱点统计**

```sql
-- 分子分母口径必须一致：一次判定机会 = 1 个样本
--   客观题：一次作答 = 1 样本（对 = 1）
--   主观题：一次作答 × 一个采分点 = 1 样本（命中 = 1）

UNION ALL ─▶ JOIN outline_nodes ─▶ GROUP BY 节点 ─▶ 命中率升序
```

## 5. 数据模型

SQLite 单文件（随包的 `data/kaoyan-seed.db` 或你自己的 `data/kaoyan.db`），9 张表 + 3 个视图。

### outline_nodes — 大纲骨架

| 字段 | 说明 |
| --- | --- |
| `id` / `parent_id` | 树形结构（自引用） |
| `level` | `board` / `chapter` / `section` / `point` / `detail` / `goal` |
| `name` | 节点名 |
| `seq` | 同级顺序 |
| `path` | 完整路径，如 `中外教育史 › 五、外国近代教育 ›（三）西欧近代教育思想与教育思潮` |
| `code` | 编号（`一、` / `（一）` / `1.`） |

### questions — 题目

| 字段 | 说明 |
| --- | --- |
| `year` | 年份（AI 生成为 NULL） |
| `source` | `2021真题·单选` / `2021真题·主观` / `AI生成` |
| `qtype` | `single` / `analysis`(辨析) / `short`(简答) / `essay`(分析论述) |
| `stem` | 题干（材料题保留 `\n` 分段） |
| `options` | JSON，如 `{"A":"…","B":"…"}` |
| `answer` | 客观题答案（A/B/C/D） |
| `outline_id` | → `outline_nodes.id`，挂载的考点 |
| `extra` | JSON，主观题存 `{"full_score": 15}`；抽过解析的话还有 `explain` / `answer_text` |

### points — 采分点（系统的核心资产）

| 字段 | 说明 |
| --- | --- |
| `question_id` | → `questions.id` |
| `seq` | 序号，用于勾选 |
| `claim` | **核心论断**（短，用于勾选按钮） |
| `evidence` | **判分依据**（长，贴近参考答案原文） |
| `outline_id` | 该点所属考点（薄弱点聚合靠它） |

### attempts / point_hits — 作答记录

`attempts`：`question_id` / `date` / `mode` / `hits` / `total` / `cause` / `note` / `student_answer` / `grade` / `session_id`

- 客观题：`hits=0/1`，`total=1`，选中的选项字母存在 `note`
- 主观题：`hits=命中采分点数`，`total=该题采分点总数`，`cause`=错因
- 主观题的**作答原文**存在 `student_answer`、**AI 批改结果**（JSON：分数/总评/命中与漏掉/逐段批注）存在 `grade`
  —— 练习日志要靠它们才能展开出"我的作答 / 批改情况"
- `session_id` 指回 `sessions`；早期直接入库的作答该列为空，日志页会把它们归到"未归属记录"

`point_hits`：`(attempt_id, point_id, hit)` —— 具体命中了哪些点。

> `student_answer` / `grade` / `session_id` 三列都由 `server.py::ensure_schema()` 在启动时幂等补齐，
> 老库不用手工迁移。

### sessions — 练习日志

每次提交一条：得分、采分点命中、`weak_snapshot`（当刻薄弱点快照 JSON）。

### papers — 试卷持久化

`single_ids` / `subjective_ids`（JSON 数组，**保持顺序**）、`status`（`active` / `archived`）。

### reports — 学习复盘报告

`session_id` / `date` / `mode` / `content`（AI 生成的 Markdown 报告）/ `metrics`（当次量化快照 JSON）。

### seed_meta — 随包题库的元信息

两列键值表（`k` / `v`），**只有 `kaoyan-seed.db` 里有**：生成时间、来源，以及各项数量
（`questions` 1057 / `real_questions` 1001 / `points` 912 / `outline_nodes` 637）。
用来核对"这个包里的题库是不是完整的"，运行时不读它。

### 三个视图（防止"查询漏过滤"这类静默错误）

| 视图 | 作用 |
| --- | --- |
| `v_real_questions` | 只含真题（排除 `source LIKE 'AI%'`）。曾因漏加这个过滤，AI 题混进"真题优先"抽取且不报错 |
| `v_questions_tagged` | 题目 + 其大纲节点名/路径/层级，省掉每次手写 JOIN |
| `v_questions_ready` | 每题是否有解析 / 参考答案（`has_explain`、`has_answer_text`） |

> 视图在 `server.py::ensure_schema()` 里每次启动重建（`DROP VIEW IF EXISTS` + `CREATE VIEW`），重建数据库后不会丢。

## 6. HTTP 接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/` `/daily` `/logs` `/reports` | 四个页面 |

| GET | `/api/logs/day/{date}` | 某一天的**题目级明细**：按练习分组，逐题给题干 / 我的作答 / 批改情况，并带 `report_id` 供跳转复盘 |
| POST | `/api/review/generate` | 给某次练习生成 AI 复盘报告（可重复生成=覆盖） |
| GET | `/api/reports` | 报告列表 + 总体趋势 |
| DELETE | `/api/reports/{id}` | 删报告（不动作答与日志） |
| POST | `/api/ai/test` | AI 连通性自检 |
| GET | `/api/daily/gen-options` | 出题设置的可选项（五档难度的名称与命题要求、默认档）——档位说明**与提示词同源**，页面不另写一份 |
| POST | `/api/daily/parse` | 学习记录 → 候选考点 |
| POST | `/api/daily/generate` | 按指定考点出题（真题优先；接受 `difficulty` 1–5 与 `thinking`） |
| POST | `/api/daily/weak-paper` | 按薄弱点出题（同样接受 `difficulty` / `thinking`） |
| POST | `/api/daily/ai-set` | **全 AI 模拟组**（20 单选 + 3 主观，刻意不用真题；接受 `difficulty` / `thinking`，返回成组质量自检报告） |
| POST | `/api/daily/grade` | 主观题批改（文本或图片） |

## 7. 数据管线：从 PDF 到题库

> **这一节是给"想从原始资料重建题库"的人看的**，日常使用不需要它 ——
> 随包的 `data/kaoyan-seed.db` 已经是重建好的成品。
> 重建需要你自备原始资料（考纲 docx/pdf、真题与解析文本），本仓库不含这些文件。

**本仓库不含任何真题解析 / 教辅 / 大纲 PDF 与扫描件**（版权原因）。有自己的资料时，按下面顺序处理：

```
① PDF/扫描件  ──OCR──▶  source/真题库/*.md
        tools/ocr_pages.py + RapidOCR
        （先渲染 300 DPI 再识别；扫描件无文字层时必需）

② 真题文本    ──AI──▶  questions（单选）
        app/ingest_years.py
        （把真题原文 + 解析原文一起交给 AI，一次输出结构化题目与答案）

③ 真题文本    ──AI──▶  questions + points（主观题 + 采分点）
        app/ingest_subjective.py

④ 大纲文本    ──规则──▶  outline_nodes
        app/build_db.py
        （正则解析 Markdown 层级，无需 AI）

⑤ 全部题目    ──AI──▶  questions.outline_id
        app/tag_questions.py
        （把题干交给 AI，从大纲"节"清单里选一个）
```

**脚本共性**：都支持 `--force` 重做、按年份过滤（如 `ingest_years.py 2021`），且**单个文件失败不中断整批**（异常隔离）。

**成本参考**：18 年真题（约 800 道单选）+ 193 道主观题（847 个采分点）+ 挂载考点，合计 **约 1 元**。

## 8. 关键实现与理由

以下都是实际踩过坑之后定下来的，改动前请先理解原因。

### 8.1 AI 生成的选项必须在程序层打乱

实测 AI 生成的单选题答案高度集中在某个字母（连出 3 道全是 B），考生会看出规律。在 prompt 里要求"均衡分布"**不可靠**，所以 `ai.shuffle_options()` 在代码里打乱选项并同步更正答案。

### 8.2 薄弱点的分子分母口径必须一致

```
每个「样本」= 一次判定机会
  客观题：一次作答 = 1 样本（对 = 1）
  主观题：一次作答 × 一个采分点 = 1 样本（命中 = 1）
```

早期版本分子来自 `point_hits`（只记命中）、分母来自 `points`（全部采分点），两边口径不同，**出现过 `2/1 = 200%` 这种不可能的结果**。

### 8.3 思考模式：批改一直开着，出题默认开但你能随时关

实测同一个问题：开启思考输出 **44 tokens**，关闭只需 **1 token**，而思考 token 按输出计费（4 元/百万）。
所以早期把 `config.json` 的 `thinking` 设成 `"disabled"`，只在批改主观题时由代码单独开启。

**出题链路现在默认开思考**（`/daily` 的「出题设置」里可随时关），因为它对题目质量的影响是实测可见的。
代价（真实生成实测，难度档 4、一套 20 单选 + 3 主观）：

| | 开思考 | 关思考 |
| --- | --- | --- |
| 输出 tokens | 26000–29000（**其中推理占约 70%**） | 约 8000 |
| 耗时 | 2.2–2.6 分钟 | 1–3 分钟 |
| 花费 | **0.11–0.13 元 / 套** | 0.04–0.05 元 / 套 |

⚠️ **开思考必须同时放宽 token 预算**，否则会以"JSON 解析失败"的形式坏掉（推理也算 completion）：
单选出题 16000 → 32000、主观题 10000 → 20000、**质检 2500 → 12000**，请求超时 180 → 600 秒。
这些都在 `config.json` 的 `generate` 段里可调。质检还加了兜底：**失败就自动关思考重跑一次**
（质检只是审阅已生成好的题，不需要那么深的推理）。

> 质检那条预算是真实生成第二轮才炸出来的：4000 全被推理吃光、正文返回空串。
> 第一轮 4000 够用、第二轮就不够 —— 预算类问题只会以"看不懂的报错"出现，必须真跑才看得见。

### 8.3.1 难度档：靠提示词的可观察描述，程序只做兜底校验

「难度」写成"难一点/简单一点"，模型基本无感。所以五档难度（偏易 / 中等 / 对标真题 / 偏难 / 极难）
每档都给**可观察的命题特征**——情境复杂度、需要几步推理、干扰项来自哪里、识记题上限——
再让模型自评 `difficulty`（1–5）。

程序层**能**确定性校验的只有两件：① 自评难度有没有贴住目标档（越档/均值偏离就带着问题重出）；
② **正确项不得明显比其它选项长**（否则学生不看内容、挑最长的就能蒙对）。

实测教训（两次真实生成对比）：模型会给全部 20 道都打"难度 4"，但 AI 质检指出其中近半是
**换了情境外壳的识记题**——"一位教师受到 X 的启发……问这体现了 X 的什么思想"，
去掉情境就是"X 的思想是什么"，换个壳而已。现已把这条写成提示词里的硬规则「**情境外壳测试**」：
**情境里的具体条件必须参与判断**，让人"背得出理论定义"仍然不足以作答。

结论：**模型自评的难度不是质量证明**。页面上会把难度分布一并显示给你，最终仍需人眼看题。

### 8.4 判断 PDF 质量不能只看单一指标

判断扫描件能否直接抽文字时，这些"直觉指标"都会被绕过：

| 指标 | 失效场景 |
| --- | --- |
| 字节数够多 | 嵌入字体缺 ToUnicode → 抽出全是乱码 |
| 中文占比高 | 页面全是水印 → 有中文但无有效内容 |
| 占比正常 | 文字层只覆盖前几页 → 内容残缺 |

**可靠的办法是抽出来看几眼。** `tools/audit_pdf_quality.py` 用「中文占比 + 每页字符数 + 最高频行占比」三指标做初筛，但最终仍需人工抽查。

### 8.5 试卷必须持久化

早期每次请求 `/api/paper` 都重新随机组卷，结果刷新页面就换卷、作答全丢。现在 `papers` 表记录当前生效的卷子，只有显式 `rebuild=1`（前端「重新组卷」）才归档旧的、生成新的。

### 8.6 前端事件绑定的选择器要与实际 DOM 一致

草稿自动保存曾经完全不生效，原因是绑定用了 `#paper input`，而**页面上根本没有 `#paper` 元素**（真正容器是 `#singles` / `#subjectives`）。这类错误不报错，只静默失效——**验证方式是在浏览器里实际点一下，看数据有没有写入**。

## 11. 已知限制

- **不含解析长文**：随包提供题目与官方答案，但客观题解析、主观题参考答案（逐字来自商业机构解析书）未随仓库分发；可用 `extract_explain.py` / `extract_subjective_answer.py` 自行补全
- **AI 定位考点可能出错**：所以保留「考点确认」步骤，由使用者增删后再出题
- **AI 生成题质量需要观察**：生成题标记 `source='AI生成'`，不参与"真题优先"抽取（查询请用 `v_real_questions` 视图）
- **薄弱点分析精度取决于作答量**：作答覆盖的考点太少时，分析会集中在少数节点上
- **2023 年主观题没有参考答案**：源文件本身未提供，补齐后仍会缺这 11 道
- **少数题目的答案存在版本差异**：2024 第 42/43、2025 第 41/42 这 4 道题，库中答案与解析文件所述不一致，未擅自改动
- **挂载粒度**：题目全部挂在 `section`；采分点绝大多数 `section`，少量 `chapter`（24）与 `board`（13）—— 这是有意保留，下推到节会丢信息
- 手机端未适配（局域网可访问，但布局未优化）
